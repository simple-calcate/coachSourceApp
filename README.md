# CoachSource —— 个人训练数据采集工具

在电脑和手机上随手记录长对话（含拍照题目），导出成能直接喂给模型训练的标准 JSONL。

---

## 一、它解决什么问题

你想给自己的模型喂"自己的数据"：你的说话方式、你的判断标准、你遇到的真实问题。
这类数据不可能靠下载现成数据集获得，只能一点一点攒。

这个工具就是那个"随手记、随时导"的本子。

**和直接用浏览器网页最大的区别：数据是你磁盘上的真实文件。**
浏览器方案存在 IndexedDB 里，iOS 有"7 天不访问就清除"的策略，清缓存也会丢。
这里每条数据保存时就写进磁盘，清缓存、换浏览器、卸载重装都不影响它。

## 二、数据存在哪

| 平台 | 目录 |
|---|---|
| Linux 桌面 | `~/.local/share/com.jx235.coachsource/` |
| Android | App 私有目录（`/data/data/com.jx235.coachsource/`，无需任何存储权限） |

目录结构：

```
<数据目录>/
├── data.json              ← 全部记录，就是这个库本身
├── images/                ← 拍照 / 上传的图片
├── sft_t2t.jsonl          ← 「镜像成固定文件」生成的，训练脚本可以直接盯这两个文件
├── pretrain_t2t.jsonl
└── export/                ← 点「导出」生成的文件
    ├── sft_t2t_2026-10-02.jsonl
    ├── images/
    └── sft_t2t_2026-10-02.zip     ← 含图片时会多一个 zip
```

**想备份，直接复制整个目录就行。** 想换机器，把目录拷过去覆盖即可。

## 三、两种导出格式

### 1. SFT 对话格式 —— 日常主要用这个

和你已有的 `sft_t2t.jsonl` 完全同构，训练脚本一行都不用改：

```json
{"conversations":[{"role":"user","content":"这道题怎么做"},{"role":"assistant","content":"先用换元法…"}]}
```

带图片时（拍照题目走这个）：

```json
{"conversations":[{"role":"user","content":"<image>\n这道题怎么做"},{"role":"assistant","content":"…"}],"images":["images/img_ab12.jpg"]}
```

这是 LLaVA / ms-swift / Qwen-VL 通用的多模态写法：正文里用 `<image>` 占位，
图片路径单独放在 `images` 数组里。带图片导出时会顺带打成 zip（jsonl + images/ 一起）。

> 勾了「附带元数据」才会多出 `id` / `tags` / `source` 字段。
> **要直接喂训练脚本就别勾**，保持和原文件一模一样。

### 2. 预训练纯文本格式

```json
{"text":"一整段连续文本……"}
```

适合你有大段笔记、文章、转写稿要一次性灌进去。
**注意**：一个人手打的数据量（几千条）扔进预训练基本不起作用，
预训练靠的是规模（你那份 846 万行的语料才叫规模）。
所以日常请优先用 SFT 格式。含图片的记录在这个格式下会被跳过并提示数量。

## 四、构建

### 桌面版

```bash
pnpm install --registry=https://registry.npmmirror.com   # 只第一次需要
pnpm desktop:build
```

产物在 `src-tauri/target/release/bundle/`。
开发调试用 `pnpm desktop:dev`（改前端代码会热更新）。

### 安卓版

安卓项目已经生成好（`src-tauri/gen/android`），**打包请在自己的终端里执行**：

```bash
./build-android.sh
```

> **为什么要你自己跑**：Gradle 靠 JVM 派生子进程工作，而 AI 助手所在的执行环境禁止
> JVM 做 `fork/exec`（实测连启动 `/bin/echo` 都会报 `error=13 权限不够`）。
> 你自己的终端没这个限制。Rust 那部分已经编译好了，所以这一步只剩 Gradle 打包。
> 首次约 10–20 分钟（要下载 Gradle 及其依赖）。

等价的手动步骤：

```bash
source env.sh                 # 加载 JAVA_HOME / ANDROID_HOME / NDK_HOME
pnpm android:init             # 只第一次需要
pnpm android:build            # 产出 APK
```

手机开 USB 调试、连上数据线，然后：

```bash
adb install -r src-tauri/target/.../*.apk
```

或者用 `pnpm android:dev` 直接推到手机上运行调试。

#### 几个必须知道的前提

- **JDK 必须是 17 或 21。** 不是越新越好——Gradle 8.x 遇到 JDK 22+ 会直接报错。
  版本选择和手机安卓版本无关，只取决于 Gradle / AGP。
- **手机是 Android 16（API 36）**，所以 SDK Platform 用的是 `android-36`。
- **16KB 内存页对齐**：Android 15 起强制要求原生库按 16KB 页对齐，
  否则 APK 在 Android 16 上装不上或启动即崩。已配好在 `.cargo/config.toml`，别删。
- iOS 编不了：Tauri 的 iOS 构建必须在 macOS + Xcode 上跑。

## 五、三个区：待导出 / 已导出 / 回收站

库页面分成三区，这是整个工具的核心组织方式：

- **待导出**：还没进训练文件的对话。日常攒数据就在这儿。
- **已导出**：已经导出成本地文件。它们**仍然会**被下一次云端同步带上。
- **回收站**：已经同步上云的对话。正文完整保留在本地，可恢复、可彻底删除。

前两个区都**不是删除**。数据一直在，随时可以勾选任意条数点「恢复到待导出」，
它们就会重新参与导出和同步。只有回收站里的「彻底删除」才会真正把数据连同图片抹掉。

完整流程：录入 → 攒在待导出 → 本地导出 → 进「已导出」 → 云端同步 → 进「回收站」。

## 六、云端同步到 GitHub

每次同步把「待导出 + 已导出」的全部对话整合上传，之后它们进入回收站。

### 准备一次

去 GitHub → Settings → Developer settings → OAuth Apps → **New OAuth App**：

- 勾上 **Enable device flow**
- Callback URL 随便填，比如 `http://localhost`
- 建好后把 **Client ID** 填进应用的「同步」页

> 为什么需要这一步：应用是纯客户端，没有服务器来接收 GitHub 的回调，
> 所以走**设备码授权（Device Flow）**——它不需要客户端密钥，也不需要服务器。
> 而且每个人都登录自己的 GitHub，数据进自己的仓库。
> Client ID 本身不是秘密，应用发布者可以内置一个让所有使用者共用。

### 每次同步

1. 「同步」页点「用 GitHub 登录」→ 浏览器自动打开 → 输入显示的短码 → 授权
2. 填仓库名（默认 `coach-source-data`），仓库不存在就点「创建仓库」
3. 点「开始同步」

它会依次做这些事：

| 步骤 | 做什么 |
|---|---|
| 切分 | 所有对话拼成 jsonl，切成若干个**严格小于 100MB** 的文件（默认 50MB 一片） |
| 图片 | 用到的图片另外打成 zip 分片，同样受上限约束 |
| 上传 | 传到 `data/2026-10-02/` 这样的日期目录；同一天再同步会变成 `2026-10-02-2` |
| 校验 | 逐个比对云端文件的**字节数和 git blob SHA-1**，全部对上才算成功 |
| 归档 | 校验通过后，本地这些对话才移进回收站 |

校验用的是 git 的 blob 哈希，也就是 `sha1("blob " + 字节数 + "\0" + 内容)`，
和 GitHub 返回的 `sha` 是同一个东西。好处是**不用把几十 MB 下载回来**比对，
就能确认云端内容和本地一字不差。

### 让别人下载

同步完会列出每个文件的直链（`raw.githubusercontent.com`），可一键复制全部。
仓库默认**私有**；想让别人直接下载，需要把仓库设为公开——应用里有开关，
但会先弹确认，因为这一步**不可逆**。

> ⚠️ 公开意味着任何人无需登录就能看到并下载全部对话。内容可能被搜索引擎抓取、
> 被别人 fork，删除后也不保证能清干净。想清楚再开。

## 七、日常怎么用

1. **录入**：选来源 → 写内容 → 保存。多轮就点「+ 用户」「+ 助手」继续加。
   右下角实时显示这条有多少字。
2. **接着往下写**：在库里点任意一条就能打开，所有轮次都在，
   光标自动落在最后一轮，直接继续追加。长对话可以分好几天慢慢攒。
3. **拍照题目**：在某一轮里点 `+`，手机上会直接调起相机。
4. **整理 AI 对话**：点「粘贴一整段 AI 对话，自动切成轮次」，
   把 ChatGPT / Claude 的对话整段贴进去，会自动按 `User:` / `Assistant:` /
   `### 用户` / `【我】` 这类标记切好。
5. **导出**：去「导出」页，选 SFT 格式 + 「只导出新增的」，点导出。

**列表里的标题默认就是你的问题**——没特意写标题时，自动取第一轮提问当标题，
所以扫一眼列表就知道每条是什么。字数会显示成 `1,234 字` / `3.2 万字`。

> 编辑中的内容会每 0.4 秒自动存草稿，误关窗口不会丢。

## 七点五、分词器（默认关闭）

一个「观察你的文本会被怎么切」的工具，基于你自己维护的词汇表做**最大前缀匹配**：

- **开启**：设置 → 分词器 → 勾选「启用分词器」。默认是关的。
- **观察**：录入页会出现「观察分词」按钮。打开后，每个轮次正文下方出现着色预览，
  **没被词汇覆盖的字**用你在「分词器 · 未被覆盖字体颜色」里选的那一种颜色标出，
  右上角实时显示覆盖率。
- **全开**：点「全开（逐 token 着色）」，每个被覆盖的 token 各着一种随机色，
  同一个 token 永远同色，用来全面检查切分结构。
- **加词**（三种方式，加完立即生效）：
  1. 在分词视图里直接**点一段被标色的字**，它就进词汇表；
  2. 在正文输入框里**选中一段文字**，点「选中文字加入分词器」；
  3. 设置 → 词汇表里手动输入，或**导入字典树文件**（跨设备搬词汇表）。
- **删词**：设置 → 词汇表，词右边的 ×。

### 导出与同步

- 本地导出时，词汇表自动以 **`tokenizer_trie.json`**（字典树）的形式和 jsonl 放在一起；
- 云端同步时，它随每批数据上传到 `data/<日期>/tokenizer_trie.json`，一样经过 SHA-1 校验；
- 词汇表为空时不产生这个文件。

### 为什么是字典树

导出结构是嵌套 trie（`{"e": 是否成词, "c": {下一字: 节点}}`），两棵树合并就是逐节点取并集，
天然适合多份导出累积。将来要训练分词器时，把历次导出合起来：

```bash
python3 tools/merge_trie.py 批次1/tokenizer_trie.json 批次2/tokenizer_trie.json -o merged.json
# 也可以直接给目录，会自动找里面的 tokenizer_trie.json
```

## 八、手机和电脑的数据怎么合到一起

两端各自导出，然后在任意一端「导入 / 合并」：

- 桌面端可以选 `.jsonl` 或 **`.zip`（连图片一起）**
- 导入时按内容指纹自动去重，重复录了也不会进两份

也可以在电脑上直接用脚本合并：

```bash
python3 tools/merge_jsonl.py 手机.jsonl 电脑.jsonl -o merged.jsonl
```

它会打印去重统计，并检查有没有"缺 assistant 回复"这类会白训的问题。

## 九、代码结构

```
web/            前端（三个平台共用这一套界面，纯 HTML/CSS/JS，无打包器）
  index.html
  styles.css
  app.js           ← 含 localStorage 兜底后端，浏览器直接打开也能用
src-tauri/      Rust 后端：存盘、导出、去重都在这里
  src/
    model.rs       数据结构
    store.rs       读写 data.json（原子写：先写 tmp 再 rename）
    exporters.rs   生成 jsonl / zip（并附带字典树导出）
    importer.rs    导入与去重
    sync.rs        GitHub 云端同步：切分、上传、校验、归档
    settings.rs    应用设置（settings.json，目前是分词器开关与颜色）
    tokenizer.rs   分词器：词汇表、最大前缀匹配、字典树导出/合并/导入
    lib.rs         命令注册
tools/
  merge_jsonl.py   命令行合并去重
  merge_trie.py    合并多份分词器字典树
  make_icon.py     生成图标
.cargo/config.toml Android 16KB 页对齐
env.sh             安卓构建环境变量
```

**为什么存数据不用数据库**：数据量是几千条级别，一个 JSON 文件全量读写是毫秒级，
换来的是零原生依赖（Android 上编译 SQLite 的 C 代码坑很多），以及"用任何文本工具都能打开看"。
真到几十万条再换 SQLite 也不迟。

## 十、常见问题

**Q：导出的文件和原来那份 `sft_t2t.jsonl` 格式一样吗？**
一样。默认不勾元数据时，每行只有 `conversations`（有图才多一个 `images`），
可以直接和原文件拼在一起、放进同一个数据集目录。

**Q：图片怎么喂给训练？**
用带图导出的 zip，解压后保持 `xxx.jsonl` 和 `images/` 的相对位置不变即可。
jsonl 里写的是相对路径 `images/xxx.jpg`，框架会按这个去找。

**Q：想改数据目录怎么办？**
桌面端目录由 Tauri 按系统规范给（`~/.local/share/<identifier>`）。
想放别处，导出时用「导出到指定目录」即可，或者把整个目录 symlink 过去。

**Q：卸载 App 会丢数据吗？**
桌面版不会（数据在 `~/.local/share`）。安卓版会——安卓卸载会清私有目录，
所以**手机上要定期导出**，别只存在 App 里。
